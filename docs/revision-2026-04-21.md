## 1. Fix ya aplicado y commiteable (listo para push)

### Bug #1 — `/proyectos` tardaba ~15s cargando

**Causa**: `ProjectCategoriesSection.tsx` y `ProjectsByCategorySection.tsx` hacían `fetch('/api/categories')` y `fetch('/api/site-config')` en `useEffect` del cliente. Mientras esperaba, renderizaba `"Cargando categorías..."`. Sumado al cold-start de Neon en SSR, daba los ~15s percibidos.

**Fix aplicado**: mover la query de categorías al SSR (`Promise.all` en `page.tsx`) y pasarla como prop al client component.

**Archivos**:
- `lib/content/categorias.ts` (NUEVO) — helper con `getCategoriasPublicas()` usando `cache()` de React
- `app/(public)/page.tsx` — agregado `getCategoriasPublicas()` al `Promise.all`
- `app/(public)/proyectos/page.tsx` — idem
- `app/(public)/proyectos/ProjectsPageClient.tsx` — recibe y pasa `categorias`
- `components/home/HomeContent.tsx` — recibe y pasa `categorias`
- `components/sections/ProjectsByCategorySection.tsx` — quitados useEffect de fetch, quitado state `loading`
- `components/sections/ProjectCategoriesSection.tsx` — idem

**Resultado medido**: `/proyectos` warm baja de ~15s a **323-795ms**. El HTML ya trae las 6 tarjetas SSR-renderizadas. Verificado con `hasLoadingTxt: false` y `hasCategoryLinks: 6` en el HTML.

### Bug #2 — SVGs 404

**Causa**: `ServiciosContent.tsx:247` y `:683` usaban `/images/backgrounds/grid-pattern.svg` y `/images/backgrounds/dots-pattern.svg` que no existían.

**Fix aplicado**: archivos SVG creados.
- `public/images/backgrounds/grid-pattern.svg` — 40×40, línea blanca
- `public/images/backgrounds/dots-pattern.svg` — 24×24, punto blanco

Ambos probados con curl → 200 OK.

## 4. Bugs y pendientes priorizados

### 🔴 P1 — `/proyectos/detalle/[slug]` cliente hace fetch + "Cargando proyecto..."

**Archivo**: `app/(public)/proyectos/detalle/[slug]/page.tsx` (2038 líneas, `'use client'`)

**Patrón**: idéntico al fix del bug #1. El page.tsx es `'use client'`, hace `useEffect` + `fetch('/api/projects/by-slug/${slug}')` (L82-106) y muestra `"Cargando proyecto..."` (L171-180) hasta que responda. API warm 466-485ms, cold hasta 2115ms.

**Plan de fix**:

1. `mv app/(public)/proyectos/detalle/[slug]/page.tsx app/(public)/proyectos/detalle/[slug]/ProjectDetailClient.tsx`
2. En `ProjectDetailClient.tsx`:
   - Cambiar `'use client'` sigue arriba (es client component)
   - Cambiar firma: `export default function ProjectDetailClient({ proyecto }: { proyecto: Proyecto })`
   - Quitar `useParams`, el state inicial `proyecto/loading/error`, el `useEffect` de fetch (L82-106), y los `if (loading)` / `if (error || !proyecto)` returns (L171-198).
   - La lógica de `useParams` ya no hace falta — el slug viene implícito en el proyecto.
3. Crear NUEVO `app/(public)/proyectos/detalle/[slug]/page.tsx` server component:
   ```tsx
   import { notFound } from 'next/navigation'
   import { prisma } from '@/lib/prisma'
   import ProjectDetailClient from './ProjectDetailClient'

   export const dynamic = 'force-dynamic'
   export const revalidate = 0

   export default async function Page({ params }: { params: { slug: string } }) {
     const proyecto = await prisma.proyecto.findFirst({
       where: { slug: params.slug, visible: true },
       include: {
         imagenes: { orderBy: { orden: 'asc' } },
         historia: { where: { activo: true } },
       },
     })
     if (!proyecto) notFound()
     return <ProjectDetailClient proyecto={proyecto as any} />
   }
   ```
4. Ajustar el type `Proyecto` en `ProjectDetailClient.tsx` para que acepte la forma real que viene de Prisma (fechaInicio es `Date`, no `string`). Puede requerir serialización con `JSON.parse(JSON.stringify(proyecto))` o un cast `as any` si el type original usa `string`.
5. Opcional: eliminar `app/api/projects/by-slug/[slug]/route.ts` si no se usa en otros lugares (hay que greppear primero).

**Dónde se usa el API `/api/projects/by-slug/`**: revisar con `grep -r "by-slug/" app components lib` antes de borrar.
